Glossary – how it works
WebRTC
Web Real-Time Communication – a browser API enabling direct P2P audio, video, and data between peers without a relay server (except for initial signaling).
ICE
Interactive Connectivity Establishment – the process of discovering and testing network paths between peers, gathering candidates (addresses) and trying them in priority order.
STUN
Session Traversal Utilities for NAT – a server that tells each peer its own public IP/port, allowing direct connection when NAT is involved.
TURN
Traversal Using Relays around NAT – a relay server used as fallback when STUN fails (e.g., symmetric NAT). DTLS-encrypted; the relay sees ciphertext only.
SDP
Session Description Protocol – a text format describing media capabilities (codecs, encryption, ICE credentials). An offer/answer exchange negotiates the connection parameters.
NAT
Network Address Translation – a router technique mapping private IPs to a shared public IP, which complicates P2P discovery (solved by ICE/STUN/TURN).
DataChannel
A bidirectional DTLS-encrypted channel for arbitrary binary or text data, built on SCTP over DTLS/ICE. Used here for file transfer (reliable, ordered).
DTLS
Datagram TLS – the encryption layer used by WebRTC for all media and data. Keys are derived locally; not even the TURN relay can decrypt the content.
